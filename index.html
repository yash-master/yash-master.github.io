03 / Selected Work
Two systems, told in full

The experience section above is the log. These two are the story behind the two biggest builds: what was broken, what I did about it, and what changed.

Enrollment Data Lakehouse Migration · Risepoint
Current
Problem

112 university partners' enrollment data lived in a legacy system with no version control and no lineage. Business rules like census survival, melt, and billing eligibility were implemented ad hoc, so the same metric could be re-derived three different ways in three different reports, and nobody could say which one was right.

Approach

Designed a Bronze-to-Silver-to-Gold dbt pipeline on Databricks Unity Catalog: Python API jobs land raw data in Bronze, 12 version-controlled dbt macros centralize the business logic in Silver, and a Gold dimensional model (fact_course_enrollment plus 8 conformed dimensions) feeds a semantic layer that defines every enrollment metric exactly once.

  • 10.6M+ rows now under governance across 112 partners, with SHA-256 surrogate keys and sentinel-aware FK resolution replacing NULL-dependent legacy patterns.
  • One governed definition per metric (new, melted, billed, month-end active) instead of three inconsistent ones per report.
  • Full lineage and replay capability via watermark-based incremental loads carrying ingestion run ID and timestamp end-to-end.
